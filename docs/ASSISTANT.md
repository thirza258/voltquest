# Circuit assistant and coding agents

English is the default. Use **Language / Bahasa** in the header to switch to Indonesian. The choice
is saved in `vq.locale` on this browser. Interface text, all 35 tutorial narratives, campaign guidance,
and component learning cards use the translation catalog. Code, pin identifiers, user project names,
serial output, and raw runtime/API diagnostics retain their original text. Switching languages does
not recreate the circuit, editor or simulation. Missing translations fall back to English.

## Ask the AI guide

Open **Circuit → AI**, or **Ask AI** above the canvas. Tutorials show the same guide under their circuit.
Select a part or a cable to focus the context, then ask about wiring, code, an objective, or the next
experiment. Every question includes a fresh snapshot of the current, possibly unsaved implementation:

- Board profile and supported runtime, code, actual components, resolved pins and wire endpoints.
- The inspected selection, simulation state, measurements, recent serial output and diagnostics.
- The current tutorial and checked steps, or campaign objective text and results.

Reference solutions, hidden hints, account credentials and other saved projects are excluded. Large
snapshots are shortened and mark omitted sections. A response can explain or propose code, but does
not edit or run the project. Conversation history lasts only in this mounted panel; clearing it,
leaving the project, or changing identity discards it. Questions and snapshots are not stored by the
VoltQuest chat service. Sending a question shares its snapshot and recent conversation with OpenRouter
and the selected model provider.

### Enable OpenRouter

Install backend dependencies with `make install`. For local development put these settings in
`backend/.env`, or export them in the shell starting the API. Docker Compose reads the root `.env`.

```dotenv
OPENROUTER_API_KEY=your-openrouter-key
AI_BASE_URL=https://openrouter.ai/api/v1
AI_MODEL=openai/gpt-4.1-mini
```

Restart the API after changing these values. The official Python **OpenAI SDK** uses OpenRouter's
OpenAI-compatible endpoint. The key stays on the backend; do not use a `VITE_*` variable for it.
The URL and model are configurable, and `AI_API_KEY` is an alternate key variable. See the
[OpenRouter SDK guide](https://openrouter.ai/docs/guides/community/openai-sdk).

Without a key the panel explains that AI help is unavailable; the simulator and MCP still work.
Requests require the player's normal session (guests work), allow 2,000 question characters and eight
history messages, and have a 45-second server deadline. There are no automatic paid retries.
The service allows 10 requests/player/minute, 60 requests/minute total, one active request/player
and four active requests total. These limits are **per server process**, not a distributed quota.
Provider failures are sanitized; the browser keeps the question for retry.

## Connect Claude Code or Codex

In the same AI section expand **Connect Claude Code / Codex**:

1. Choose **Create MCP token**, then copy the token. It is displayed only after creation, expires
   after 30 days and is stored on the server only as a hash. Replacing it invalidates the old token;
   **Revoke access** also removes the shared context.
2. Set `VOLTQUEST_MCP_TOKEN` in the environment that launches your coding agent.
3. Copy the relevant configuration from the panel and merge it into your existing configuration.
   The panel uses this site's API URL, including the final slash in `/api/mcp/`.
4. Choose **Share current context**, restart the agent, and check its `/mcp` connection list.
5. Ask: “Read my VoltQuest context and create a project that helps me finish this circuit.” Open
   the returned sandbox link, or use **Project → My projects**, to inspect and run the result.

Claude Code project configuration (`.mcp.json`):

```json
{
  "mcpServers": {
    "voltquest": {
      "type": "http",
      "url": "https://pcb.nevatal.id/api/mcp/",
      "headers": { "Authorization": "Bearer ${VOLTQUEST_MCP_TOKEN}" }
    }
  }
}
```

Claude Code supports environment expansion in HTTP headers. See its
[MCP configuration documentation](https://code.claude.com/docs/en/mcp#environment-variable-expansion-in-mcpjson).

Codex configuration (`~/.codex/config.toml`):

```toml
[mcp_servers.voltquest]
url = "https://pcb.nevatal.id/api/mcp/"
bearer_token_env_var = "VOLTQUEST_MCP_TOKEN"
```

See the [Codex MCP documentation](https://developers.openai.com/codex/mcp/). For local development use
the URL generated by the panel, normally `http://localhost:5173/api/mcp/`. The agent must be able to
reach that machine. On another deployment domain, add the hostname to `MCP_ALLOWED_HOSTS` and any
browser origin to `CORS_ORIGINS`. The shipped allowlist covers `pcb.nevatal.id` and local development.

### What agents can do

The Streamable HTTP endpoint uses the official Python MCP SDK (`mcp` 1.x) and a separate opaque
bearer credential. A player JWT cannot call MCP, and an MCP token cannot log in, modify account
settings, or spend the site's OpenRouter key. The agent uses its own model connection.

| Tool | Behavior |
| --- | --- |
| `get_project_guide` | Circuit schema, placement rules, supported runtime and workflow |
| `get_board` | Exact board pins, capabilities, starter placement and breadboard layouts |
| `get_component` | Pin footprint, properties, defaults and learning notes |
| `get_current_context` | Latest explicitly shared circuit/lesson snapshot |
| `list_projects` / `get_project` | Read the token owner's saved projects |
| `create_project` | Save a private project, with a supplied circuit or valid starter controller |
| `update_project` | Edit an owned private project using `updated_at` from `get_project` |

All six boards are supported. Updates detect intervening changes and require re-reading on conflict.
Public projects must be copied to a new private project before agent editing. There are no publishing,
deletion, account, shell, or firmware execution tools. Geometry, pins, properties, controller count,
and document sizes are validated before saving.

Context sharing is explicit, not a live browser connection. Snapshots become unreadable after 24 hours;
share again after edits. Agent changes affect saved projects and do not replace unsaved work in an open
tab. Reopen the saved project to inspect the result; an older local draft is offered separately.
Only the browser can run firmware, including the restricted Raspberry Pi GPIO Python model.

## Maintenance and verification

`frontend/src/i18n/id.json` maps English messages to Indonesian. Add display translations with
`useI18n().t(message, values)`, preserving identifiers and user content. Adjacent tests check narrative
and component-guide coverage, language persistence and editor preservation.

`content/mcp-catalog.json` is generated from the actual deterministic board/component registries:

```bash
node scripts/export-mcp-catalog.mjs
make check
```

Regenerate after changing profiles, layouts, footprints or component defaults. The catalog equality
test fails on drift. ESP32 pin placement is checked across both breadboards in world coordinates.

Automated checks exercise OpenAI SDK requests with a mocked HTTP transport, input limits and provider
failures; MCP initialize/discovery, all six board saves, ownership, stale updates, expiry/revocation and
invalid geometry; and frontend snapshot, language, cancellation and configuration behavior. Local
Chromium verification exercised context sharing → MCP create/edit → saved sandbox → real blinking
LED, plus English/Indonesian switching and a 390 px layout. A live paid OpenRouter answer and actual
Claude Code/Codex CLI sessions still require the operator's credentials and configuration.

## Drone context and agents

Drone workspaces use the same guide and explicit Share current context control. Snapshots add only
known drone specification fields, mounts, typed connector endpoints, course/flight settings and live
attitude/RPM/rail/gate telemetry. Arbitrary metadata and full blackbox histories are excluded. Selected
connectors remain in the selection context; current unsaved code is retained and hidden solutions
remain excluded. Language switching does not recreate the build or simulation.

The MCP guide includes the drone schema, allowed parameters, mounts and teaching firmware notes;
component lookup includes drone sockets and compatible mounts. Existing project tools can create
and edit owned private drone projects using complete CircuitDocs. Agent saves never overwrite an
open tab, publish a project or run firmware. See [DRONE.md](DRONE.md) for the actual APIs and pin map.
Regenerate `scripts/export-drone-catalog.mjs` output after drone metadata changes as well as the
existing MCP board/catalog export after board changes.
